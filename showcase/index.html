Section 01 · Philosophy

The Frontend Dilemma

Web engineering today forces developers into an unnecessary binary choice: endure the bare limitations of plain HTML, or surrender to the sprawling complexity of full-stack frameworks.

Side A: Vanilla HTML

Too Sparse

Plain HTML is wonderfully portable, fast, and native. But building real applications requires modern primitives that plain HTML simply lacks.

  • ✖ No reactive state — every UI update requires manual querySelector and string concatenation
  • ✖ No declarative abstractions — closing tags and repetitive boilerplate clutter templates
  • ✖ No client routing — multi-view experiences require complex custom hash scripts
  • ✖ Spaghetti event listeners scattered across loose JavaScript files

Side B: Heavyweight Frameworks

Too Heavy

React, Next.js, and Vue solve reactivity beautifully, but they introduce massive tooling friction and conceptual baggage for standard web projects.

  • ✖ 1,500+ dependencies inside half a gigabyte of node_modules
  • ✖ Compulsory compilation pipelines (Vite, Webpack, Babel, Rollup, PostCSS)
  • ✖ Hydration mismatches, server/client boundary confusion, and breaking upgrade cycles
  • ✖ 140+ KB runtime bundle overhead before your app renders a single character

The Middle Ground: Breeze Framework

The Sweet Spot

Breeze was created to sit squarely between these extremes. It provides the core application primitives you actually want—declarative markup, auto-batching reactive state, 10,633 SSR ops/sec, components with slots, list virtualization, client routing, design utilities, and a fast CLI—while honoring the simplicity of the web platform. No build step required, no dependencies, ~49.80 KB gzip footprint (40.65 KB Brotli).

Section 03 · Specifications

Core Engine Capabilities

Fifteen deliberate architectural features packed into a single, cohesive zero-dependency runtime.

SPEC 01

Declarative Syntax & Dot Shorthand

Indentation-based .breeze grammar eliminates closing-tag mismatches by construction. Includes dot/hash shorthand (div.card-glass#profile) for rapid markup without XML boilerplate.

SPEC 02

Auto-Batching Reactive Store

Microtask-batched signal graph (queueMicrotask). Coalesces multiple synchronous state mutations into a single surgical DOM flush: 5,000 updates in 5.63 ms (3.21× faster than unbatched).

SPEC 03

High-Throughput SSR & Template Compiler

Blazing server-side rendering at 10,633 ops/sec with AST template memoization (Parser.compileTemplate). Delivers byte-for-byte deterministic HTML output and instant client hydration.

SPEC 04

Component Architecture & Slots

Reusable component declarations with @def ComponentName(props), positional argument binding, and transclusion via @slot for nested composition without runtime abstraction penalty.

SPEC 05

Keyed Reconciliation & List Virtualization

Longest Increasing Subsequence (LIS) keyed diffing via @each item in list [key=id]. Clamps massive datasets with @virtual each item in rows [height=36, overscan=3] down to minimal active DOM nodes.

SPEC 06

Client-Side Outlet Router

Full SPA router supporting hash and HTML5 pushState modes, dynamic route params (/user/:id), animated transition outlets (@outlet [fade]), and automatic active link class synchronization.

SPEC 07

Conditionals & Control Flow

First-class branch directives directly in template markup: @if condition, @elif condition, and @else allow reactive conditional rendering without ternary soup.

SPEC 08

Universal Web Components

Convert any Breeze template into a W3C standard custom element with Breeze.defineElement('my-element', template, options). Drop natively into vanilla HTML, React, Vue, or Svelte.

SPEC 09

Framework Interop Adapters

Zero-overhead bridge layers (BreezeReact and BreezeVue) enabling bidirectional state synchronization and seamless component embedding inside legacy React and Vue codebases.

SPEC 10

Lightweight HTTP & Resource Layer

Zero-dependency HTTP client (breeze-http.js) featuring LRU in-memory caching (88,968 ops/s cache hit rate), exponential backoff retries, JSON serialization, and request interceptors.

SPEC 11

Extensible Plugin Architecture

Lifecycle hooks (beforeInit, afterMount, beforeDestroy) and custom action keywords with Breeze.plugin() in under five lines of plain JavaScript.

SPEC 12

Decoupled Global Event Bus

Lightweight publish-and-subscribe message bus (Breeze.on, Breeze.emit, Breeze.off) enabling decoupled communication across isolated components and Web Components.

SPEC 13

Cerulean Ocean Design System

Complete design token palette (Cerulean Blue, Ocean Navy, Washed Tomato, Slime Green), 60+ CSS utility classes, glassmorphism cards, accessible forms, and auto dark mode in breeze.css.

SPEC 14

Zero-Dependency CLI Toolchain

Unified developer toolchain with breeze dev (SSE live reload), breeze build --spa, breeze doctor (environment health checker), and breeze bench performance testing.

SPEC 15

Native GEO, AEO & SEO Directives

Direct markup support for @seo, @schema (JSON-LD), @aeo (Answer Engine summaries), and @geo (LLM knowledge graphs) with automated llms.txt and sitemap.xml.

CLI Reference

breeze init [name]

Scaffolds a clean starter application containing index.html, starter app.breeze, and minimal package.json.

breeze dev [port]

Starts a local HTTP server with automatic Server-Sent Events (SSE) live reload. Watches source files and updates the browser instantly.

breeze doctor

Audits project files, syntax tree integrity, missing router outlets, and environment configuration.

breeze build [file] [--spa]

Compiles your declarative .breeze file into dist/index.html. In --spa mode, inlines all JS/CSS into one standalone file.

breeze serve [dir] [port]

Runs a production-grade static file server with client-side SPA routing fallback support. Zero npm server dependencies.

Why ~49.80 KB Matters in Practice

Network latency and JavaScript execution parsing are primary bottlenecks for web performance. Every 50 KB of unneeded framework overhead delays First Contentful Paint and increases memory pressure on mobile devices.

At 49.80 KB gzip (222.34 KB raw, 40.65 KB Brotli), Breeze ships a complete, batteries-included application toolkit: indentation grammar compiler, microtask auto-batching signals, 10,633 SSR ops/sec, component slots, keyed list reconciliation & virtualization, SPA outlet router, HTTP layer, and Cerulean Ocean design tokens—with zero npm dependencies.

Section 14 · Clarifications

Frequently Asked Questions

Straightforward answers regarding architecture, capabilities, and production readiness.

Why not just use vanilla HTML and JavaScript?
Vanilla HTML is ideal for static documents, but creating reactive applications quickly degenerates into dozens of document.querySelector calls, manual innerHTML updates, and scattered event listeners. Breeze provides structured declarative markup, automatic reactive text bindings, and client-side routing while preserving the lightweight spirit of plain HTML.
Why not use React or Next.js?
React is exceptional for enterprise applications with sprawling component libraries and complex state trees. However, for marketing sites, prototypes, calculators, or lightweight SPAs, React introduces an enormous dependency footprint (>1,400 packages), mandatory build steps, virtual DOM overhead, and complex hydration issues that simply aren't needed.
Does Breeze require a build step?
No. You can drop breeze.js into any HTML file with a standard <script> tag and call Breeze.init('app.breeze') directly in the browser. A build step is completely optional, provided via breeze build solely for producing single-file inlined distributions.
Is Breeze truly dependency-free?
Yes. The core runtime has zero external npm dependencies. Both breeze.js and breeze-cli.js are written strictly with native web platform APIs and standard Node.js built-in modules.
Can I use normal HTML elements in Breeze?
Any standard HTML tag is supported directly as a Breeze element (e.g. h1, p, button, input, textarea, section, div). Breeze also recognizes standard HTML attributes in modifier brackets such as [type=email, placeholder="Enter email..."].
How does reactivity work without a Virtual DOM?
During the initial render pass, the Breeze renderer compiles text interpolation targets and registers direct DOM text pointers (_bzPatchTargets). When state signals mutate, Breeze auto-batches updates into a microtask and modifies only the registered text nodes in place, completely skipping full tree re-renders and virtual DOM diffing.
Can Breeze be extended with custom plugins?
Yes. The plugin API (Breeze.plugin(name, { install, actions })) allows developers to hook into the lifecycle and define custom action keywords that can be triggered directly in markup via @click -> customAction().
Is Breeze suitable for production environments?
Yes. Breeze compiles with breeze build --spa --minify into a production-ready, self-contained HTML bundle that can be deployed on Vercel, Netlify, Cloudflare Pages, GitHub Pages, or any static hosting service with zero configuration.
How does Breeze support GEO, AEO, and SEO natively?
Breeze includes native top-level directives: @seo for automated OpenGraph, Twitter cards, meta descriptions, and canonical tags; @schema for JSON-LD structured data; @aeo for AI answer engine summaries and voice speakable selectors; and @geo for entity and fact citation mapping. During breeze build, these directives are pre-rendered into static HTML, and production sitemap.xml and robots.txt files (configured for Googlebot, GPTBot, ClaudeBot, and PerplexityBot) are automatically generated with zero plugins required.
