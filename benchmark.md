### How to read the numbers

* Chrome suites report the **median of 3 runs** (`BZ_BENCH_RUNS=3`) with sd in the console log.
* Absolute milliseconds move with machine load and temperature — on this Pentium, repeat
  runs vary ±20–40%. **Only same-session, same-machine comparisons are meaningful.**
  That is why every table below is one session, and old sessions are kept separately
  under “Historical baselines”, never mixed into the headline claims.
* Timing method: click dispatched via CDP, elapsed until `requestAnimationFrame` +
  `setTimeout(0)` after the handler. That is *frame-callback* timing, **not** a guaranteed
  paint timestamp — an honest approximation, identical for every framework.
* Heap numbers come from `Performance.getMetrics` (`JSHeapUsedSize`) right after the
  workload. They are GC-timing sensitive and can swing 2× between runs; treat them as
  order-of-magnitude, not exact.

1. **Krausest DOM ops** — Breeze is fastest in **6 of 8** operations vs React 19 / Vue 3.5 / Preact 10 / Vanilla.

6. **Honest losses kept**: row-append throughput (React/Vue faster), raw SSR vs VDOM serializers, Preact-core bundle. See §8.

50 databases × 5 queries re-rendered every animation frame for 100 consecutive frames.

| :--- | :---: | :---: | :---: | :---: |
| **🌊 Breeze v2** | **60.1 FPS** | **16.65 ms** | **56 / 99** | **2,328.3 KB** |
| Vanilla JS | 18.5 FPS | 54.09 ms | 99 / 99 | 1,364.5 KB |
| Preact 10.29.8 | 18.7 FPS | 53.46 ms | 99 / 99 | 1,628.3 KB |
| Vue 3.5.42 | 15.2 FPS | 65.93 ms | 99 / 99 | 1,965.1 KB |

### Takeaway
VDOM frameworks queue whole-tree reconciliations per frame and sit at ~15–19 FPS in headless
Chrome on this CPU. Breeze patches only changed text nodes through cached element references
and holds **60.1 FPS — 3.3× React 19**. Dropped-frame counting is strict (>16.6 ms);
headless CDP has no vsync, so treat FPS as comparative throughput, not display refresh.

Full page (nav, header, 10 feed items, footer) rendered to string in Node, 1,000 iterations.

| SSR Engine | Throughput (pages/sec) | Mean Latency (μs) | HTML Payload Size |
| :--- | :---: | :---: | :---: |
| **Breeze SSR (pre-parsed AST)** | **2,345 pages/sec** | **426.4 μs** | **2,097 bytes** |
| **Breeze SSR (raw DSL string)** | **2,831 pages/sec** | **353.2 μs** | **2,097 bytes** |
| Virtual DOM Serializer (Preact-style) | 14,454 pages/sec | 69.2 μs | 2,289 bytes |

> Raw-DSL ≈ pre-parsed because `Parser.parse` hits the v2 LRU cache. The remaining gap to
> the VDOM serializer (~5×) is structural: Breeze lexes an indentation DSL and expands

> (v1.1: ~530 pg/s) via the parse cache, precompiled `{token}` templates and `join('')`
> string building. SSR speed is not the product claim — instant pre-rendered FCP plus
> non-destructive hydrate is.

## 🧠 7. Architectural Analysis: Why Breeze Is Fast Here

### 1. Keyed template cloning vs virtual DOM diffing
React/Preact/Vue build an in-memory representation of all 1,000 rows and reconcile it on
every update. Breeze keeps direct DOM references per key (`[key=id]`) and patches only
changed text nodes — hence 18.1 ms vs 38.5–62.1 ms on “update every 10th row”.

### 2. Surgical row operations
* **Update 10th**: untouched rows are never visited (18.1 ms, fastest this session).
* **Select**: one class toggled via `data-bz-key` lookup, no list reconciliation (11.9 ms, fastest).
* **Delete**: the node is unlinked; siblings are not re-evaluated (0.9 ms, 69× React 19).
* **Swap**: v2 LIS keeps the longest already-ordered subsequence and moves only the rest —
  51.2 ms vs 324.4 ms for React 19 (6.3×). Vanilla’s hand-rolled swap (44.6 ms) remains the
  ceiling for a two-node exchange; Breeze is 13% behind it.

### 3. Minimal heap overhead
No vnode/fiber/component instances per row — just the data array plus element references:
4,944 KB retained vs 46,281 KB for React 19 (9.4×). Vanilla (3,555 KB) shows the floor.

## ⚖️ 8. Honest Trade-offs and Limitations

1. **Row appends**: Breeze 809 ms vs Vue 447.8 / React 460.5 ms. Per-row template
   interpolation + class mapping dominates bulk inserts. The prefix fast-path avoids the
   old O(n) move sweep but creation itself is the cost. Genuine loss — not claimed otherwise.
2. **Raw SSR vs VDOM serializers**: 2,831 vs 14,454 pg/s. A DSL that parses, expands
   components and resolves bindings per node cannot beat function calls per node. Breeze SSR
   exists for instant pre-rendered FCP + hydrate, not for winning pg/s.
3. **Preact-core bundle**: 4.79 KB gzip beats Breeze’s 30.64 KB — it also contains no router,
   no reactivity primitives beyond `h`/render, no SSR, no design system.
4. **Absolute ms are machine-specific**: this Pentium N3700 is ~5–10× slower than desktop
   silicon. Re-run on your hardware with the commands in §6; ordering — not milliseconds —
   is the portable claim.
5. **Heap numbers are GC-noisy**: Vue’s 45.6 MB this session vs 36.0 MB previously is
   collection timing, not a leak. Read heap as order-of-magnitude.

### Where Breeze wins
1. Content-heavy & marketing SPAs: pre-rendered FCP with zero build tooling.
2. High-frequency local updates: tables, tickers, dashboards.
3. Constrained devices: low memory, low power, older browsers (Chrome 88+/FF 85+/Safari 14+).
4. Long-term archival: zero dependencies means zero dependency rot.

### Where heavy frameworks win
1. Huge third-party ecosystems (AG-Grid, MUI, AntD and hundreds more).
2. Streaming server components / island orchestration (Next.js App Router and peers).
3. Very large teams already trained on JSX and React testing patterns.
4. Sustained 60 fps **display** animation with vsync guarantees — headless CDP FPS here
   measures frame-callback throughput, and all frameworks drop frames under this workload.
